## 1. 定位与边界

Kafka 提供企业微服务可靠异步消息的统一生产、消费、提交、幂等、重试和死信治理。消费者可继承手动提交或框架自动提交策略，默认手动提交。

组件不保证业务天然“恰好一次”，不允许以消息成功发送代替业务结果成功；业务消费者必须明确幂等语义。

## 2. 技术栈与依赖

- Spring for Apache Kafka、Kafka Client。
- JSON Starter 作为默认载荷序列化；保留 Schema 扩展点。
- 依赖 Common、JSON、Logging；Observability 可选。

## 3. 核心能力

1. 统一生产者、消费者、Topic、Header 和消息标识契约。
2. 手动提交与框架自动提交两种明确策略。
3. 至少一次投递、幂等消费、分级重试、死信和人工处置。
4. 批量、并发、背压、顺序、超时和优雅停机治理。
5. 消息追踪、延迟、积压、失败和丢弃指标。

## 4. 实现要求

- 默认手动提交必须在业务处理成功后提交；失败不得提前提交。
- 自动策略只在框架确认处理成功后提交，并暴露明确扩展接口。
- 重试次数和间隔必须有界；不可重试错误直接进入死信流程。
- 消费者必须支持幂等键；重复消息不得造成重复业务结果。
- 消息中只携带必要标识和事件事实；缓存消费者重新读取主库，不依赖事件携带完整业务数据。
- Kafka 消费线程模型独立，不复用 Async 普通业务线程池。

## 5. 配置与扩展

- `framework.kafka.producer.*`
- `framework.kafka.consumer.*`
- `framework.kafka.retry.*`
- `framework.kafka.dead-letter.*`
- 抽象基类：手动提交消费者、框架自动提交消费者。
- SPI：幂等存储、错误分类、死信处理与载荷 Schema。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 手动提交 | 处理成功与失败分别消费 | 仅成功消息提交 |
| 自动提交策略 | 使用框架自动消费者 | 成功后提交，异常不提交 |
| 重复消息 | 重复发送相同幂等键 | 业务结果仅产生一次 |
| 重试与死信 | 注入可重试和不可重试异常 | 路由、次数和间隔符合规则 |
| 背压 | 降低下游处理能力并压测 | 消费受控，无无界内存增长 |
| 优雅停机 | 消费处理中终止应用 | 已接收消息完成或安全重新投递 |
| Broker 中断 | 断开并恢复 Kafka | 不伪成功，恢复后可继续处理并告警 |

## 7. 交付物

自动配置、消费者策略基类、消息契约、幂等/重试/死信规范、故障演练和验证应用。
