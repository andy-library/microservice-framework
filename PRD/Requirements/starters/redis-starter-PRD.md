# Redis Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-redis-starter` |
| 引入策略 | 按需显式引入 |
| 定位 | 分布式缓存及 Redis 通用能力 |

## 1. 定位与边界

Redis 为核心微服务独立 Redis 集群和非核心服务共享集群提供统一客户端、缓存、锁、限流、计数器和排行榜能力。

业务应用必须在代码中明确控制缓存读写。禁止缓存全表；热点读取必须优先命中缓存，未命中时实时读库并回填。V1 不提供缓存版本和 Lua 批量脚本能力。

## 2. 技术栈与依赖

- Spring Data Redis、Lettuce、连接池。
- 支持独立、哨兵和集群模式。
- 依赖 Common、JSON、Logging；Observability 可选。

## 3. 核心能力

1. 统一 Key 命名、TTL、序列化、连接和超时治理。
2. Cache-Aside 工具、空值防穿透、热点 Key 和击穿保护扩展。
3. 分布式锁、限流、计数器、排行榜和批量删除能力。
4. 集群隔离、共享集群命名空间和容量诊断。
5. 故障告警、恢复、重连和操作审计。

## 4. 实现要求

- 默认 JSON 使用 JSON Starter；序列化实现选择不得影响 Redis API 契约。
- 所有 Key 必须具有 TTL 或经过显式永久 Key 审批；禁止无界集合。
- 非读操作变更数据后必须第一时间更新或失效缓存；极低概率下允许极短暂不一致，但必须可监控和补偿。
- 批量删除使用非阻塞扫描与删除策略，禁止生产使用全量阻塞命令。
- 锁必须有租约、所有权校验和超时；失败时不得假装获取成功。

## 5. 配置与扩展

- `framework.redis.mode`
- `framework.redis.namespace`
- `framework.redis.command-timeout`
- `framework.redis.cache.default-ttl`
- `framework.redis.lock.*`
- SPI：Key 规范、TTL 策略、缓存加载与故障补偿钩子。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 三种部署模式 | 分别连接独立、哨兵和集群环境 | API 契约一致，连接与故障切换正常 |
| 热点缓存 | 并发访问同一未命中 Key | 数据库回源受控，无雪崩 |
| 写后更新 | 写库成功后更新/失效缓存 | 后续热点读取获得最新数据 |
| Redis 中断 | 断开 Redis 并持续请求 | 按业务策略失败或受控回源，立即告警 |
| 锁安全 | 模拟超时、误释放和进程退出 | 非所有者不能释放，锁最终可恢复 |
| 批量删除 | 对大量 Key 执行清理 | Redis 无长时间阻塞，过程可观测 |
| 共享集群隔离 | 两个应用使用同一集群 | Key 和权限互不污染 |

## 7. 交付物

自动配置、通用 API、Key/TTL 规范、缓存可靠性指南、压力基准、故障演练和验证应用。
