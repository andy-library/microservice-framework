# Async Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-async-starter` |
| 引入策略 | 按需显式引入 |
| 定位 | 通用进程内异步执行治理 |

## 1. 定位与边界

Async 提供命名、隔离、有界、可观测并支持优雅停机的进程内异步能力。适用于可接受进程故障丢失或已有外部补偿的非关键任务。

关键且不可丢失的异步业务必须使用 Kafka 或持久化任务；禁止业务自行创建不受治理线程池。

## 2. 技术栈与依赖

- Java 21 Executor、Spring Task Execution。
- 依赖 Common、Logging；Observability 可选。

## 3. 核心能力

1. 按用途命名和隔离的有界线程池。
2. 上下文快照、传播、清理和异常处理。
3. 队列、并发、超时、取消和拒绝策略治理。
4. 线程池指标、任务耗时、积压、拒绝和失败告警。
5. 优雅停机和未完成任务诊断。

## 4. 实现要求

- 每个线程池必须显式声明用途、容量、队列和拒绝策略；禁止无界队列。
- 上下文传播后必须清理，防止线程复用串扰。
- 拒绝不得静默丢弃；调用方必须感知或通过明确补偿处理。
- 应用停机停止接收新任务，在限定时间内完成或取消剩余任务并记录。
- XXL-JOB 可复用上下文契约，但分布式调度职责不进入本组件。

## 5. 配置与扩展

- `framework.async.executors.<name>.*`
- `framework.async.shutdown.*`
- `framework.async.context.*`
- SPI：上下文传播器、拒绝处理器、任务装饰器。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 线程池隔离 | 压满一个命名池并调用另一个 | 另一线程池不受影响 |
| 上下文传播 | 并发提交不同上下文任务 | 上下文正确且执行后清理 |
| 队列过载 | 超过容量持续提交 | 按策略拒绝，不静默丢失、不无限增长 |
| 异常处理 | 任务抛出异常 | 异常可观察，调用或补偿方可感知 |
| 优雅停机 | 有运行中与排队任务时停机 | 按时完成/取消并记录明细 |
| 依赖边界 | 检查依赖树 | 不引入 Kafka、XXL-JOB 或 Web |

## 7. 交付物

自动配置、统一执行 API、线程池容量指南、上下文契约、压力基准和验证应用。
