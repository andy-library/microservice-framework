# Field Encryption Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-field-encryption-starter` |
| 引入策略 | 按需显式引入 |
| 定位 | 应用侧字段加密、密钥隔离和轮换治理 |

## 1. 定位与边界

Field Encryption 为需要保护敏感字段的应用提供统一加解密、密文格式、密钥版本和轮换能力。

组件不替代传输加密、数据库访问控制或全盘加密；不允许应用自行发明加密算法和密文格式。

## 2. 技术栈与依赖

- Java Cryptography Architecture，使用批准的 AEAD 算法。
- 可配置 KMS 提供者，并提供满足基础安全要求的默认密钥提供方式。
- 依赖 Common、JSON、Logging；Database 集成可选。

## 3. 核心能力

1. 随机加密、解密、密文识别和密钥版本。
2. 仅在明确检索场景允许的确定性加密扩展。
3. 密钥隔离、缓存、轮换、重加密和吊销。
4. 字段注解/显式 API、批量处理和失败分类。
5. 加解密操作指标与安全审计事件。

## 4. 实现要求

- 默认使用随机 AEAD 加密；确定性加密必须经过风险评审并限制字段。
- 密文必须包含格式版本、算法标识和密钥版本，不包含明文。
- 密钥不可写入代码、日志、配置明文或密文载荷；默认提供方式也必须支持安全外部注入。
- 解密失败、未知密钥和密文损坏必须失败关闭，禁止回退明文。
- 轮换期间新旧密文均可读取，新写入使用新版本，并支持受控重加密。

## 5. 配置与扩展

- `framework.field-encryption.provider`
- `framework.field-encryption.keys.*`
- `framework.field-encryption.rotation.*`
- SPI：`KeyProvider`、字段策略、重加密任务和安全事件监听。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 加解密 | 对支持类型执行往返测试 | 明文正确恢复，密文不泄漏信息 |
| 非确定性 | 重复加密同一明文 | 默认生成不同密文 |
| 密钥隔离 | 扫描代码、配置、日志和载荷 | 无密钥明文 |
| 轮换 | 切换密钥版本并读取历史数据 | 新旧可读，新写使用新版本 |
| 密文损坏 | 修改密文或使用未知密钥 | 失败关闭并产生安全事件 |
| Provider 替换 | 使用默认与测试 KMS Provider | 公共契约一致 |

## 7. 交付物

自动配置、加密 API、密文格式规范、Provider SPI、轮换手册、安全测试和验证应用。
