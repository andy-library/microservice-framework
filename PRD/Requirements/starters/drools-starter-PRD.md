# Drools Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-drools-starter` |
| 引入策略 | 按需显式引入 |
| V1 决策 | 支持规则版本与动态刷新，保留灰度扩展点 |

## 1. 定位与边界

Drools Starter 为需要规则引擎的应用提供统一规则加载、校验、执行、版本、动态刷新和运行治理。

组件不建设规则管理平台，不替代业务对规则语义的审核，也不允许规则执行绕过应用安全和数据边界。

## 2. 技术栈与依赖

- Drools/KIE。
- 依赖 Common、JSON、Logging；配置 Starter 与 Observability 可选接入。

## 3. 核心能力

1. 规则包加载、编译、验证、激活和执行。
2. 规则版本、校验状态、发布时间和当前激活版本。
3. 动态刷新、原子切换、失败回滚和最后有效版本。
4. 执行超时、并发隔离、输入输出约束和异常治理。
5. 命中、耗时、失败、版本和变更事件；保留灰度路由扩展点。

## 4. 实现要求

- 新规则必须先完成语法、依赖、契约和回归校验，验证成功后才能激活。
- 刷新必须原子切换；加载失败继续使用最后有效版本并立即告警。
- 规则执行必须有时间和资源边界，不允许任意 I/O 或访问未授权服务。
- 每次执行必须可定位规则集与版本，但不得记录敏感业务输入。
- 灰度能力 V1 只定义稳定路由扩展接口，不交付完整灰度平台。

## 5. 配置与扩展

- `framework.drools.rulesets.<name>.*`
- `framework.drools.refresh.*`
- `framework.drools.execution.*`
- SPI：规则来源、版本仓库、发布校验器和灰度路由器。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 规则加载 | 加载合法与非法规则包 | 合法包可执行，非法包拒绝激活 |
| 动态刷新 | 执行期间发布新版本 | 新请求原子切换，进行中请求不受破坏 |
| 回滚 | 发布无法加载或回归失败版本 | 保留最后有效版本并告警 |
| 执行边界 | 构造超时、异常和高并发规则 | 执行受控，应用资源不被耗尽 |
| 版本追踪 | 执行多个规则版本 | 每次结果可定位准确版本 |
| 灰度扩展 | 注入测试路由器 | 指定流量可路由指定版本 |

## 7. 交付物

自动配置、规则执行 API、版本与发布规范、灰度扩展契约、故障演练和验证应用。
