# Database Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-database-starter` |
| 引入策略 | 按需显式引入 |
| 默认模式 | ShardingSphere-JDBC + 读写分离；默认关闭分库分表 |

## 1. 定位与边界

Database 为每个微服务的独立数据库提供统一访问、读写路由、事务、迁移和可靠性扩展能力。分库分表、幂等和 Outbox 均为显式启用能力。

组件不提供跨微服务分布式事务默认方案，不允许多个微服务共享表所有权，也不能替代业务对事务边界和缓存更新的明确设计。

## 2. 技术栈与依赖

- Spring JDBC/事务抽象、连接池、ShardingSphere-JDBC。
- 数据库迁移工具采用单一受治理方案。
- 依赖 Common、JSON、Logging；Observability 可选接入。

## 3. 核心能力

1. 数据源、连接池、SQL 超时、慢 SQL 和异常分类治理。
2. 默认读写分离；事务内和写后读按规则路由主库。
3. 显式分库分表配置、路由规则校验和边界诊断。
4. 本地事务模板、只读事务、隔离级别和超时治理。
5. 数据库迁移、幂等记录和 Outbox 可靠事件扩展。

## 4. 实现要求

- 默认关闭分库分表，但 ShardingSphere-JDBC 能力可用；读写分离默认开启。
- 主库故障、读库延迟和路由异常不得返回伪成功；写后读取旧值的窗口必须受控。
- 事务必须设置超时；禁止在数据库事务中执行不可控远程调用。
- Outbox 与业务数据必须同一本地事务写入，由独立发布器异步发送并支持幂等。
- 迁移必须前向兼容滚动发布；破坏性变更必须分阶段执行。

## 5. 配置与扩展

- `framework.database.datasource.*`
- `framework.database.read-write-splitting.*`
- `framework.database.sharding.enabled=false`
- `framework.database.transaction.*`
- `framework.database.outbox.enabled=false`
- SPI：路由提示、幂等键、Outbox 序列化与发布器。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 默认读写分离 | 验证应用读写并记录路由 | 写入主库，普通读走读库 |
| 写后读一致性 | 写入后立即读取 | 按规则路由主库，不返回旧数据 |
| 事务治理 | 模拟超时、回滚和嵌套事务 | 回滚正确，超时可诊断 |
| 分片开关 | 默认与显式开启分别启动 | 默认不分片，开启后规则生效 |
| 读库故障 | 断开读库 | 按策略降级或失败并告警，不伪成功 |
| Outbox | 模拟提交、发布失败与重复消费 | 业务与事件原子落库，最终可重试且幂等 |
| 滚动迁移 | 使用前后两个应用版本执行迁移测试 | 双版本可并行运行 |

## 7. 交付物

自动配置、读写路由规范、事务规范、迁移规范、Outbox/幂等扩展、故障演练和真实数据库验证应用。
