# Audit Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-audit-starter` |
| 引入策略 | B 端后台管理应用强制且不可关闭；其他应用按需 |
| 定位 | 可靠、可追溯、防篡改的操作审计 |

## 1. 定位与边界

Audit 记录后台管理能力的关键操作，覆盖操作者、对象、变更、结果、来源和关联上下文。B 端应用引入后不得被业务配置关闭或篡改。

组件不等同于普通业务日志，不审计所有 C 端请求，也不替代数据库业务流水。

## 2. 技术栈与依赖

- Spring AOP/事件、Database Outbox 或可靠 Kafka 投递。
- 依赖 Common、JSON、Logging；Database/Kafka/Security 按实现组合。

## 3. 核心能力

1. 审计注解/API、操作者、对象、动作、前后差异、结果、IP、请求 ID 和 Trace。
2. 可靠落地、重试、幂等、防篡改和保留期治理。
3. 高风险操作的同步审计确认与失败关闭策略。
4. 审计查询访问控制、导出控制和访问行为再审计。
5. 敏感字段脱敏与最小化记录。

## 4. 实现要求

- B 端验证应用必须证明审计无法由普通应用配置关闭。
- 普通操作可通过 Outbox/可靠消息异步落地；高风险操作按策略要求审计成功后才返回成功。
- 审计记录只能追加，修改或删除必须受专门权限控制并留下证据。
- 审计失败必须第一时间告警，并保留待补偿数据。
- 不记录密码、Token、密钥和不必要的敏感原值。

## 5. 配置与扩展

- `framework.audit.storage.*`
- `framework.audit.reliability.*`
- `framework.audit.high-risk.*`
- `framework.audit.retention.*`
- SPI：操作者解析、差异提取、存储和风险分类。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| B 端强制 | 尝试通过配置禁用审计 | 启动失败或审计仍强制生效 |
| 完整记录 | 执行成功、失败和拒绝操作 | 必需字段齐全，结果真实 |
| 可靠性 | 中断审计存储/消息后执行操作 | 普通操作可补偿且告警；高风险按策略失败关闭 |
| 防篡改 | 尝试普通修改和删除记录 | 被拒绝并产生安全事件 |
| 查询权限 | 未授权用户查询或导出 | 请求被拒绝并审计 |
| 敏感保护 | 执行含敏感数据操作 | 审计记录无禁止明文 |

## 7. 交付物

自动配置、审计 API、强制策略、可靠性设计、字段规范、权限规范、故障演练和验证应用。
