# Common Starter PRD

Author: Andy Yang

| 属性 | 内容 |
| --- | --- |
| 制品 | `microservice-framework-common-starter` |
| 引入策略 | 所有应用强制显式引入 |
| 定位 | Framework 最底层、无业务语义的公共契约与工具 |

## 1. 定位与边界

Common 统一日期时间、分布式 ID、错误码、分页、金额、轻量上下文和通用工具，禁止应用重复设计同类基础能力。

Common 不依赖其他 Framework Starter，不承载 Web、数据库、缓存、日志实现或业务领域模型。新增工具必须具有跨应用复用价值、稳定契约和完整测试，禁止成为无边界工具箱。

## 2. 技术栈与依赖

- Java 21、Spring Boot 自动配置与配置元数据。
- Java Time、`Clock`、`BigDecimal`、不可变值对象。
- 默认分布式 ID 使用雪花类算法；保留可替换 `IdGenerator` SPI。
- 仅允许轻量依赖，禁止引入 Web、Actuator、数据库客户端和远程中间件客户端。

## 3. 核心能力

1. 日期时间：统一 `LocalDateTime` 业务模型、显式配置时区、可注入 `Clock`、格式化和区间工具。
2. ID：统一 `IdGenerator`，支持默认方案、批量生成、节点标识校验和时钟回拨保护。
3. 错误码：稳定、唯一、可归属的错误码模型及异常基类。
4. 分页：统一页码、游标、排序输入与分页结果模型，不绑定具体数据库框架。
5. 金额：统一精度、舍入规则和币种表达，禁止使用浮点数表示金额。
6. 轻量上下文：请求 ID、用户 ID、服务身份等键值契约；不依赖追踪实现。
7. 通用工具：只提供经过评审的字符串、集合、校验等稳定能力。

## 4. 实现要求

- 时区来自 `framework.common.time-zone`，禁止依赖操作系统默认时区；持久化和跨服务传输必须保留明确时区约定。
- ID 默认全局唯一；节点冲突、非法节点号和不可接受的时钟回拨必须启动失败或快速失败并报警。
- 上下文必须支持显式创建、读取、快照和清理，防止线程复用导致泄漏。
- 错误码必须包含模块、类别和编号；重复错误码在构建期被阻断。
- 工具 API 保持线程安全、空值语义明确，不隐藏网络或磁盘 I/O。

## 5. 配置与扩展

- `framework.common.time-zone`
- `framework.common.id.type`
- `framework.common.id.worker-id`
- `framework.common.id.clock-backward-tolerance`
- SPI：`IdGenerator`、`FrameworkClockProvider`、错误码目录校验器。

## 6. 验收标准与方法

| 场景 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 强制基础能力 | 最小应用引入 Common 并启动 | 自动配置可用，无额外中间件依赖 |
| 时区一致性 | 在不同系统时区运行同一契约测试 | 输出与计算结果一致 |
| ID 唯一性 | 多线程、多节点生成至少千万级 ID | 无重复、吞吐达到基准、异常可诊断 |
| 时钟回拨 | 注入可控 `Clock` 模拟回拨 | 按配置等待或失败，不生成重复 ID |
| 上下文隔离 | 在线程复用与并发场景执行测试 | 上下文不串扰、不泄漏 |
| 错误码治理 | 构造重复和非法错误码项目 | `mvn verify` 必须失败并指出冲突 |
| 依赖边界 | 执行依赖树规则检查 | 不含其他 Starter 和重型客户端 |

## 7. 交付物

Starter 源码、配置元数据、公共 API 文档、错误码规范、时区规范、ID 部署说明、契约测试和最小示例。
